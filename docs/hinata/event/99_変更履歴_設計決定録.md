# イベント管理・セットリスト・ライブガイド (event) 変更履歴・設計決定録 (ADR)

## 2026-08-09 イベント系列バグ修正・セットリスト編集/表示の改善

### 不具合修正
* **系列（hn_event_series）が新規保存されない不具合**: イベント管理画面で未登録の系列名を入力して保存しても、系列マスタに登録されず「系列なし」でイベントが保存されていた。原因は、系列入力（テキスト + datalist）の JS が既存名にマッチした場合のみ `series_id` をセットし、新規名の自動作成フローが存在しなかったこと。修正として、フォーム送信時に系列名がありかつ `series_id` が空の場合、先に `save_event_series.php` を呼んで系列を作成し、返却IDをセットしてからイベントを保存するようにした（`event_admin.php`）。
* **セットリストのブロック行の内容が保存されない不具合**: `collect()` でブロックのラベルを `row.querySelector('.setlist-label-input')` で取得していたが、MC行とブロック行の双方が同クラスの入力欄を持つため、DOM 上で先に来る MC 側の空欄を拾い、ブロックのラベルが常に空で保存されていた。`.row-mc` / `.row-block` にスコープした取得へ修正（`setlist_edit.php`）。
* **セットリスト表示でブロックが "other" 等と表示される不具合**: `block_kind` の内部キーをそのまま表示していたため、ラベル未入力時に "other"/"session_other" が見えていた。日本語ラベルマップ `$blockKindLabels`（告知/ダンスセッション/セッション/その他）を追加して表示するよう修正（`setlist_show.php`）。

### ADR-007: アンコール区分（encore）を曲行以外へも適用
* **変更内容**: encore（本編/EN/W EN のセクション区分）を、従来の「曲行のみ有効」から曲・MC・ブロックの全種別で設定可能に拡張した。編集画面ではアンコール区分セレクトを行種別セレクトの直後に共通配置し、`SetlistModel::saveForEvent()` は entry_type を問わず encore を保持、`setlist_show.php` は全行の encore を見て ENCORE / W ENCORE 見出しを挿入する。
* **背景・理由 (Why)**: アンコール開始直後の MC（煽り等）を「アンコールセクション内」として登録できず、本編扱いになってしまっていた。実際のライブ構成を正しく表現するため、区切りを曲以外にも付与できる必要があった。
* **見送った代替案**: セクション区切り専用の行種別を新設する案。既存の encore カラムで表現でき、データ構造を増やさずに済むため見送り。

### ADR-008: セットリスト編集のUX刷新（D&D並替・途中挿入・曲検索コンボボックス）
* **変更内容**: (1) 行の並替を上下ボタンからドラッグ&ドロップ（ドラッグハンドル起点）へ、(2) 行間ホバー/フォーカスで出現する「＋」による途中挿入、(3) 曲選択を `<select>` からテキスト部分一致で絞り込むコンボボックス（hidden `song_id` を確定）へ変更した。
* **背景・理由 (Why)**: 手作業での並替・挿入・曲選択の操作性を改善するため。特に楽曲数が多いと `<select>` からの選択が煩雑だった。
* **見送った代替案**: 外部 D&D ライブラリの導入。依存を増やさず素の HTML5 Drag&Drop で要件を満たせるため見送り。

### ADR-009: セットリストのTSV一括インポート
* **変更内容**: 「一括インポート」モーダルで TSV（列: タイプ/内容/センター/区分）を貼り付け、クライアント側 `parseSetlistTsv()` で解析してフォーム行へ一括反映する機能を追加。曲名は完全一致優先＋部分一致で照合し、未一致は未選択の行として追加・レポート表示。既存行は置き換え、DB 保存は既存「保存」ボタンで確定するプレビュー方式とした。
* **背景・理由 (Why)**: 1曲ずつ手入力する運用に加え、他所で用意したセットリストを一気に取り込みたいニーズに対応するため。
* **見送った代替案**: サーバー側でのインポートAPI新設。既存の照合ロジック（allSongs/allMembers）がクライアントに揃っており、プレビュー→既存保存フロー再利用で完結するため見送り。

### 表示改善（セットリスト閲覧）
* ナンバリングを**楽曲行のみ**に変更（MC/ブロックは採番しない）。行左端にタイプ別アイコン（曲=音符/MC=マイク/ブロック=レイヤー）を追加。楽曲のリリース名を行右端から曲名のすぐ右へ移動。

## 2026-06-07 初版作成
* **変更内容**: ソースコードリーディングに基づき、event サブドメインの設計書一式（11〜23）を初版作成した。
* **背景・理由 (Why)**: 既存実装のドキュメント化。イベント管理・セットリスト・ライブガイドの3領域を1サブドメインとして統合的に設計書化した。
* **見送った代替案**: イベント・セットリスト・ライブガイドを個別のドキュメントセットに分離する案。テーブル間の結合が密であり、分離するとER図や処理フローの記述が重複するため、統合を採用した。

### ADR-001: 4ビューモード（カレンダー/タイムライン/ダッシュボード/マスタディテール）の並列提供
* **変更内容**: イベント一覧画面に4つの表示モードを並列提供する設計とした。
* **背景・理由 (Why)**: 利用シーンによって最適な表示形式が異なる（月単位の予定確認→カレンダー、時系列の振り返り→タイムライン、KPI把握→ダッシュボード、詳細編集→マスタディテール）。
* **見送った代替案**: 単一のリスト表示に統一する案。情報密度と操作性のバランスが取れないため見送り。

### ADR-002: hn_event_series による系列グルーピング
* **変更内容**: イベントの上位くくり（ツアー、単発ライブシリーズ等）を hn_event_series テーブルで管理する。
* **背景・理由 (Why)**: 同一ツアーの公演を横断的に管理（セットリスト共有、参戦実績の集計等）するため。
* **見送った代替案**: hn_events にタグカラムを持たせてグルーピングする案。リレーション情報（ツアー名、期間等）の管理に限界があるため見送り。

### ADR-003: hn_user_events_status によるユーザー別参加ステータス管理
* **変更内容**: イベントへの参加ステータス（参加予定/参加済み/不参加等）をユーザー×イベントの中間テーブルで管理する。
* **背景・理由 (Why)**: hn_events 本体にステータスを持たせると複数ユーザー対応ができない。座席情報・感想メモもユーザー単位で保持する必要がある。
* **見送った代替案**: hn_events にカラム追加する案。マルチユーザー対応が不可能なため見送り。

### ADR-004: セットリストの構造化保存（曲行 + MC/ブロック行 + 複数センター）
* **変更内容**: hn_setlists に楽曲行以外のメタ行（MC、アンコール区切り等）を track_type で区分して保存し、hn_setlist_centers でセンター情報を別テーブルに分離する。
* **背景・理由 (Why)**: 実際のライブセットリストにはMC・ブロック区切り・複数センター（Wセンター等）が存在し、単純な楽曲リストでは表現できない。
* **見送った代替案**: JSON カラムにセットリスト全体を格納する案。検索性・集計性が低下するため見送り。

### ADR-005: ライブガイドの楽曲確度（confidence）管理
* **変更内容**: hn_event_guide_songs に confidence カラムを設け、セットリスト入りの確度を段階管理する。
* **背景・理由 (Why)**: 初参戦者向けガイドでは「ほぼ確実に演奏される曲」と「演奏される可能性がある曲」を区別する必要がある。
* **見送った代替案**: 確度なしのフラットな楽曲リストとする案。優先度付きの予習ガイドを提供できないため見送り。

### ADR-006: 影ナレーション（shadow narration）の独立テーブル化
* **変更内容**: 影ナレ情報を hn_event_shadow_narrations + hn_event_shadow_narration_members で管理する。
* **背景・理由 (Why)**: 影ナレはイベント内の複数箇所（開演前・中間・終演後等）で発生し、各回に複数メンバーが担当する。hn_events のカラムでは表現できない。
* **見送った代替案**: hn_events に shadow_narration_text カラムを追加する案。複数回・複数メンバーの構造化ができないため見送り。

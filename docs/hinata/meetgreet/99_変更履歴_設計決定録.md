# ミーグリ（お話し会）& ネタ帳 (meetgreet) 変更履歴・設計決定録 (ADR)

## 2026-08-09 ネタ帳にアーカイブ機能を追加

### ADR-007: ネタのアーカイブステータス（`archive`）追加
* **変更内容**: `hn_neta.status` に `archive` を追加した。「使用済み（`done`）」とは別軸の保管ステータスで、消化とは区別してネタを退避する用途。UI ではカードを薄表示（`opacity: 0.35`）+「アーカイブ」バッジ（紫）で表し、専用「アーカイブ」フィルタでのみ閲覧、デフォルトの「未使用」フィルタでは非表示とする。`done` とは排他で、一方を ON にすると他方は OFF になる。`updateStatus()`（`update_neta_status.php`）は許可値を `stock` / `done` / `archive` に限定してバリデーションし、登録メンバーサイドバーの集計に保管数（`archived_count`）を追加した。
* **背景・理由 (Why)**: 「もう使わないが削除はしたくない」「一旦しまっておきたい」ネタを、使用済み（消化）とは意味を分けて管理したいニーズがあった。論理削除（`delete`）とも異なり、閲覧・復帰が可能な状態として保持する。
* **見送った代替案**: (1) 使用済みフラグの多値化で代用する案。使用済みと保管は意味が異なり混在させると集計・フィルタが破綻するため見送り。(2) 別テーブルへの退避。ステータス1列の追加で足り、既存の一覧取得（`status != 'delete'`）にそのまま乗るため見送り。

## 2026-06-07 初版作成
* **変更内容**: ソースコードリーディングに基づき、meetgreet サブドメインの設計書一式（11〜23）を初版作成した。
* **背景・理由 (Why)**: 既存実装のドキュメント化。ミーグリ管理とネタ帳を1サブドメインとして統合的に設計書化した。
* **見送った代替案**: ミーグリとネタ帳を別ドキュメントセットに分離する案。ネタ帳はミーグリ準備の文脈で使われるため、統合を採用した。

### ADR-001: forTUNE meets 当選テキストの自動パース取り込み
* **変更内容**: 当選結果テキストを貼り付けるだけで日付・部名・メンバー・枚数を自動パースし、hn_meetgreet_slots に一括登録する仕組みとした。
* **背景・理由 (Why)**: 手動入力は項目数が多く煩雑。当選通知の書式は概ね定型であり、正規表現パースで十分な精度が得られる。
* **見送った代替案**: CSVインポート方式。ユーザーがCSV加工する手間が発生するため見送り。

### ADR-002: チャット形式レポ（4種メッセージタイプ）
* **変更内容**: hn_meetgreet_report_messages に sender_type カラムを設け、member（メンバー発言）/ self（自分発言）/ thought（内心）/ narration（ナレーション）の4種を区分する。
* **背景・理由 (Why)**: ミーグリのやり取りは単なるテキストログではなく、「誰が何を言ったか」「そのとき何を感じたか」を構造的に記録することで、振り返りの質が向上する。
* **見送った代替案**: 自由記述テキストエリア1つに全て記載する案。構造化された表示・フィルタリングができないため見送り。

### ADR-003: レポートメッセージの暗号化
* **変更内容**: hn_meetgreet_report_messages の content カラムを暗号化して保存する（alter_encrypted_columns_to_text.sql で TEXT 型に変更済み）。
* **背景・理由 (Why)**: ミーグリでの会話内容はプライベートな情報であり、DB 直接アクセス時にも平文で読めないようにする必要がある。
* **見送った代替案**: 暗号化なしの VARCHAR 保存。セキュリティ要件を満たせないため見送り。

### ADR-004: ネタ帳のメンバー×ステータス管理
* **変更内容**: hn_neta にメンバーID・ステータス（未使用/使用済み）・お気に入りフラグを持たせ、メンバーごとのネタ管理を実現する。
* **背景・理由 (Why)**: 推しメンバーごとに「次に何を話すか」を管理する運用ニーズがある。使用済みフラグにより同じネタを繰り返し使うことを防止できる。
* **見送った代替案**: メンバー紐付けなしの汎用メモ方式。メンバー別フィルタリングができないため見送り。

### ADR-005: hn_neta_tags によるタグシステム
* **変更内容**: ネタにタグを付与するため、hn_tags マスタ + hn_neta_tags 中間テーブルの構成を採用した。
* **背景・理由 (Why)**: ネタの分類（質問/感想/報告等）をユーザーが自由に定義・拡張できるようにするため。
* **見送った代替案**: hn_neta に JSON 配列でタグを持たせる案。タグ名の正規化や集計が困難なため見送り。

### ADR-006: ミーグリレポートアバターのカスタマイズ
* **変更内容**: hn_meetgreet_report_avatars テーブルを設け、レポート内のメンバーアバター画像をユーザーが個別にアップロード・カスタマイズできるようにした。
* **背景・理由 (Why)**: デフォルトのメンバー画像だけでなく、ミーグリ時の衣装写真等をアバターとして使いたいニーズがある。
* **見送った代替案**: hn_member_images をそのまま使用する案。レポート固有のカスタマイズができないため見送り。
